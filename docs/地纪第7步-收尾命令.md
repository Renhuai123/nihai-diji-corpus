# 地纪第 7 步收尾命令（2026-11-19 写，等 Astra 全量写完后照着跑）

适用：P31 P33 P35（Astra 写主稿 → Grok 核 → Astra 按意见改）；P37 另见文末。
规矩：只在本机出文件，**不 git push、不建仓库、不公开**；出稿只写到 `../康奈尔样稿/`，不要加 `--out=`（那是往笔记仓库写的）。
站长 11-18 定地纪第 6、7 步不用 Claude 写内容：下面每一步要么是程序，要么是 Grok / Astra。
并发上限：本机自己起的子进程合计不超过 4；Grok 最多 3 路；后台写手还在跑时 Astra 只能再开 1 路，写手跑完后可开 2 路。

所有命令都在这个目录下跑：

```bash
cd "<工作目录>/第0步"
PY=../.venv-vision/bin/python
```

## 0. 先确认 Astra 全量写完、块齐了

```bash
tail -5 日志/堪舆-写手全量-astra-1119.log          # 三集都出现「结束」才算写完
for e in P31 P33 P35; do $PY -c "
import json,sys; from pathlib import Path
d=Path('按句拼接/试点/$e-堪舆笔记块'); n=[b['块'] for b in json.load(open(d/'分块.json'))]
miss=[k for k in n if not (d/f'块{k}-astra.json').exists()]
print('$e', len(n), '块，缺', miss or '无')"; done
```
有缺块就补跑写手（已写好的块会自动跳过）：`$PY cornell_write_trio.py write P33 all --by astra --路数 2`

## 1. 程序核对 Astra 原稿（不调接口，几秒）

```bash
for e in P31 P33 P35; do $PY cornell_render.py $e --堪舆 --check --by=astra; done
```
报告写 `按句拼接/试点/<集>-堪舆笔记块/校验报告-astra.json`。结构问题、板书帧不在清单、引文不中要先看一眼；改写多是 Astra 的已知特点，原字率高、引文段少是正常的。

## 2. Grok 逐条核（11-19 实测每块 10–18 分钟，3 路；P31 剩 7 块 + P33 + P35 约 2–3 小时）

```bash
nohup caffeinate -is sh -c 'for e in P31 P33 P35; do '"$PY"' cornell_grok_check.py $e all --by astra --路数 3; done' \
  > 日志/堪舆-grok核稿-全量-$(date +%m%d).log 2>&1 &
```
- 输出 `核对-grok-块N.json`（逐条 通过 / 要改 / 删 + 问题类 + 理由 + 材料原文 + 建议改法 + 用时），原始回复在 `核对原始/`。
- 断了重跑同一条命令即可：已核过、且稿子 sha1 没变的块跳过。P31 块 1–3 11-19 已核过，会自动跳过。
- 汇总（不调接口）：`$PY cornell_grok_check.py P33 --by astra --汇总`
- 看「材料原文 没核上」：Grok 抄的原文程序在材料里找不到的，那条意见要人看一眼（可能是 Grok 自己改了字）。

## 3. Astra 按核稿意见改（11-19 实测每块 1–2 分钟，只改被标的几条）

```bash
nohup caffeinate -is sh -c 'for e in P31 P33 P35; do '"$PY"' cornell_revise.py $e all --by astra --路数 2; done' \
  > 日志/堪舆-astra改稿-全量-$(date +%m%d).log 2>&1 &
```
- 只把 Grok 判「要改 / 删」的条目交给 Astra；输出 `块N-astra-改.json`，里面的「改稿记录」写着改 / 删 / 不同意保留（带理由）/ 没回 / 被拒，以及程序比对「只动了被标条目」的结果。
- Grok 全判通过的块不调 Astra，原样复制。
- 断了重跑同一条命令即可。汇总：`$PY cornell_revise.py P33 --by astra --汇总`
- 汇总里「比对」若出现「有越界」，或「没回」「被拒」不为 0，先看那块的改稿记录再往下走（必要时 `--重跑` 那一块）。

## 4. 程序核对改后版

```bash
for e in P31 P33 P35; do $PY cornell_render.py $e --堪舆 --check --by=astra --改 --list; done
```
报告写 `校验报告-astra-改.json`。和第 1 步的数字对比：不应多出结构问题、帧号偏、引文不中。

## 5. 选全集总结（Astra 挑，约几分钟一集）

```bash
for e in P31 P33 P35; do $PY cornell_pick_summary.py $e --by astra --改; done
```
- 用 `提示词/选总结读手提示词-堪舆.md` 原文（原来是 Claude 子代理挑；地纪改成 Astra 挑，想换 Grok 加 `--选手 grok`）。
- 输出 `全集总结选条-astra-改.json`；程序核序号是否存在、条数是否在 8–10 / 4–7 / 3–5、是否升序，有问题打 ⚠。
- 已有就不重挑；要重挑先把旧文件改名。想先看发出去的提示词：加 `--只看提示词`（存到 `日志/`）。

## 6. 出网页和 md

```bash
D=$(date +%Y-%m-%d)          # 第二个参数是页面上「整理」的日期；不给就会写成 2026-11-11
for e in P31 P33 P35; do $PY cornell_render.py $e $D --堪舆 --by=astra --改; done
```
输出 `../康奈尔样稿/<集>-堪舆-整集第一稿-astra-改.html` 和 `.md`。说明栏会写「Astra 6.2 max 分段起草，Grok 4.7 high 逐条核过、Astra 6.2 max 按核稿意见改过」。
出完自己打开网页看一遍（全集总结、目录、各块表格、待核折叠），不要只看程序输出。
